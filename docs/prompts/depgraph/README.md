# Depgraph Prompt Pack

This folder is the canonical prompt pack for building the tau2 dependency-graph pipeline.

Current source-of-truth architecture:

- `/Users/eligottlieb/Documents/tau2-bench/design/tau2/dependency_graph_domain_plan.md`

State vocabulary for all prompts/templates in this folder:

- projected world paths (for example `agent.lines[active_line].status`)
- `user.*` projected causal paths for user-side state
- binding ids (assistant-known values) produced by explicit tool-backed `knowledge-only` actions

## Two Adapter Paths

The depgraph pipeline supports two adapter paths that share the same graph contract,
sampler, and preflight but diverge at the "last mile" compilation:

### tau2 path (Steps 00 → 01 → 02 → 03 → 04–09)

Full user-simulator environment. Produces tau2 `Task` JSON with `initialization_actions`,
`env_assertions`, `action_expectations`, personas, sync rules, and stop-gate checking.
Use for domains with human-in-the-loop simulation (support agents, collaborative tasks).

### verifiers path (Steps 00 → 01 → 02v → 03 → 04v)

Agent-only `StatefulToolEnv`. Produces `DepgraphTaskConfig` objects with `start_world`,
`goal_world`, tool functions, and system/task prompts. Goal checking via `DepgraphRubric`
at episode end. Use for pure tool-use domains (browser automation, API interaction).

Choose the adapter path in Step 00 before beginning authoring.

## Why these prompts exist

We are implementing this system through two parallel artifacts:

1. Prompt-authored files (what coding agents write)
2. Deterministic code (what validates, solves, and compiles those files into tasks)

These prompts define the authoring contract for coding agents.

## Authoring Boundaries

Use this split to avoid ambiguity and accidental over-automation:

### tau2 path

1. **Authored by coding agent**
   - `domain_scope.md`
   - `personas.yaml`
   - `graph_contract.yaml`
   - `stop_gate_map.yaml`
   - `sampling_request.yaml`
   - `runtime_defaults.yaml`
   - `task_specs.runtime.yaml`
   - runtime domain files (`data_model.py`, `user_data_model.py`, `tools.py`, `user_tools.py`, `environment.py`)
2. **Generated by deterministic pipeline**
   - `task_specs.sampled.yaml` via `run_sampler`
   - `task_context_bindings.yaml` via `run_context_bindings`
   - `task_specs.runtime.scaffold.yaml` via `run_runtime_scaffold`
   - `task_narrative_briefs.yaml` via `run_runtime_scaffold`
   - `task_specs.runtime.yaml` bootstrap via `run_runtime_init`
   - stop-gate runtime injection updates via `run_stop_gate_inject`
   - `review_bundle.md` via `run_review_bundle`
   - `tasks.depgraph.json` via `run_compile`

### verifiers path

1. **Authored by coding agent**
   - `domain_scope.md`
   - `graph_contract.yaml`
   - `sampling_request.yaml`
   - `tools.py` (standalone functions with `db` arg)
   - `verifiers_config.py` (system prompt + task prompt factory)
2. **Generated by deterministic pipeline**
   - `task_specs.sampled.yaml` via `run_sampler`
   - `DepgraphTaskConfig` objects via `compile_for_verifiers()`

### Hard rules (both paths)

- Do not manually edit generated structure (`required_actions`, `required_precedence`, sampled start/goal intent) except via upstream source files and reruns.
- Terminal end states must be declared in `sampling_request.yaml` via `terminal_profiles`; do not create shorter tasks by stopping in intermediate repair states.
- If the domain needs many related starts, prefer `seed_schemas` in `sampling_request.yaml` over hand-maintained concrete seed lists.
- (tau2 only) Semantic enrichment happens in runtime fields only.

8. `07-runtime-tools-and-assertions.md` (refine/extend runtime callables only if needed)

4. `03-task-intents.md`
5. `04v-verifiers-compile-and-verify.md` (compile + system prompt + smoke test)

## Fail-Closed Reporting Contract

At the end of each step, always report:

1. file edited
2. command(s) run
3. pass/fail
4. if fail: smallest next fix and blocked artifact

## Cross-Step Guardrails

- `CHECKLIST.md` is the global consistency checklist to run after each major step.
- Hard gate rule: every command step must pass before the next step starts.
- Before simulation or sign-off, generate `review_bundle.md` and run `05-gap-review.md`
  in authoring-audit mode against that bundle plus the source files it cites.
